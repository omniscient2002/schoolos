## P1 — data exposure / release blockers

### P1-1 · Name-match roster↔user bridge leaks another child's homework submissions to a parent
- **Where:** `server/src/plugins/family.view/index.js:72-82` (`/parent/home` assignments join) and
  `:118-131` (`/parent/child/:id/timeline` submissions join). The bridge matches `lower(su.name) = lower(child.name)`
  on **any** user row — no `role='student'` check, no uniqueness check, no structural link.
- **Repro (executed, evidence in cycle log):**
  1. owner enables family.view: `POST /plugins/family.view/enable {version:"1.0.0",class:"C",permissions:[...]}` → 200
  2. seed has 3 roster students named **Diya Nair in grade 8** and **3 in grade 10** (seed name generator + migration 031's second student).
  3. `student2@meridian.edu` (user **Diya Nair**, grade-8 student) submits homework via `/plugins/teacher.classroom/homework/:id/submit` (3 submissions).
  4. Parent (`parent@meridian.edu`) is linked (family.child_link) to the **grade-10** "Diya Nair" roster row.
  5. `GET /parent/child/<grade-10-id>/timeline` → **200** with the grade-8 Diya Nair **user's** submissions:
     `History: Past-due HW … — late`, `Science: Plants mini-report — submitted`, `Mathematics: Fractions worksheet — submitted`.
  A parent of child A reads child B's submission titles/subjects/late-status whenever the two children share a name —
  a name collision the seed itself produces (6× Diya Nair, 6× Rohan Singh, 6× Vihaan Bose, …).
- **Also affected:** `teacher.classroom` "missing" inbox (`teacher.classroom/index.js:173-184`) — one student's
  submission cleared the missing flag for **all 3** same-named roster rows (over-match, see P3-2), and `/parent/home`
  assignments (`family.view/index.js:76-79`) has the same any-name-match join.
- **Suggested fix:** stop matching on names. Add a structural link — `app.users.student_id uuid REFERENCES app.students(id)`
  (migration, backfilled by exact name+grade+section where unambiguous, else NULL) — and match `sub.student_id = u.id AND u.student_id = <roster id>`.
  Until that ships, at minimum: require `su.role='student'` AND require the name-match to resolve to **exactly one** user row
  (fail closed when the match is ambiguous), and carry grade/section equality into the join.

## P2 — privilege / correctness

### P2-1 · Cross-class homework submissions accepted (no grade gate on the submit door)
- **Where:** `server/src/plugins/teacher.classroom/index.js:98-101` — the submit door's homework SELECT fetches
  `id, title, subject, due_at, status` but **not `class_grade`**, and nothing compares the student's roster grade to it.
- **Repro:** grade-8 student user submits the grade-6 homework posted above → `POST .../homework/<grade-6-id>/submit` → **200**
  (`submissionId 499fc711…`). The one-shot pin and tenant RLS hold; only the class gate is missing.
- **Impact:** wrong-class submissions pollute the review desk and the missing-state math; a student can file work into any
  class's open homework.
- **Suggested fix:** SELECT `class_grade` too and reject with a plain-language 400 ("This homework is for class X") when
  it ≠ the student's roster grade — which needs the same structural student link as P1-1 (a name-bridge inside a *gate* would
  repeat the P1-1 mistake; ids only).

### P2-2 · Decide-door role aliasing: `/coord/substitution/decide` approves ANY coordinator-owned action (incl. staff leave) and emits a spurious `sub.assign.v1`
- **Where:** `server/src/plugins/coord.view/index.js:316-353` — the door checks `owner_role='coordinator'` but never that the
  action *is* a substitution (no `code`/`payload.kind` check), and line 341 emits `sub.assign.v1` on every approval.
- **Repro:** teacher files staff leave (`POST /teacher/leave`) → kernel action `teacher.leave.<id>` (owner_role coordinator);
  `POST /coord/substitution/decide {action_id:<leave action>, decision:"approved"}` → **200** `code:"teacher.leave.beff8907…"`,
  status approved, `event:"sub.assign.v1"` emitted for a leave. The leave mirror (`/teacher/leave/mine`) shows `casual:approved`.
- **Impact:** the audit/event spine now claims a substitution was approved for a leave decision; any future coordinator-owned
  action type is silently decidable through this door with the wrong event semantics.
- **Suggested fix:** pin the door to real substitution actions — require `a.code LIKE 'substitution.%'` (or `payload.kind='substitution'`,
  whichever convention ops.timetable mints) and return 409 "This decision is not a substitution" otherwise; move the
  `sub.assign.v1` emit behind that same check.

### P2-3 · Kernel decide lets the principal approve coordinator-owned staff-leave actions (SoD scope gap)
- **Where:** `server/src/routes.js:386` — `ownerOk = a.owner_role === req.user.role || ['owner','principal'].includes(req.user.role) && a.owner_role !== 'finance'`
  — the principal matches via role-membership, so the "owning authority" check is bypassed for every non-finance owner_role.
- **Repro:** same leave action; `POST /actions/<id>/decide {decision:"approved"}` as principal → **200** approved + notification executed.
  (Teacher self-approve correctly 403s; coordinator via the kernel door correctly 403s as non-owner.)
- **Impact:** staff leave is approvable by the principal while the product copy and the coord door both declare the coordinator
  the deciding authority; SoD reduces to "anyone senior", not "the routed authority".
- **Suggested fix:** require exact `owner_role === req.user.role` on the kernel decide (keep an explicit, documented escalation
  list if product wants principal override — and stamp those decisions `override` in `policy_ref`).

### P2-4 · Jti-less tokens bypass revocation entirely, and logout still audits "session revoked"
- **Where:** `server/src/app.js:38-41` — the denylist check is `if (payload.jti) {...}`: a validly-signed token **without** a jti
  claim is unverifiable-against-the-denylist by construction. `app.js:184-196` — the logout door writes the audit outcome
  "session revoked (jti denylist)" **unconditionally** and returns ok even when `req.auth.jti` is absent and nothing was revoked.
- **Repro:** forge `HS256` token with the dev secret (`server/.env`), claims `{sub,role,tenant,name}` + **no jti** →
  `/me` 200; `POST /auth/logout` → 200 `{ok:true}` + audit row "session revoked (jti denylist) · …"; `/me` again → **200**.
  The session is not revoked; the ledger says it was. (With a jti the flow is correct: 200 → logout → 401 `session ended`.)
- **Context:** `tests/auth-revocation.test.js:51-54` pins "legacy tokens (no jti) still authenticate" as an intentional
  compat window — but A3's stated guarantee ("logout must actually end a session", migration 038 header) does not hold for them,
  and the audit row is false either way.
- **Suggested fix:** (a) close the compat window — post-038, refuse jti-less tokens at `authenticate` (they only exist from
  pre-038 mints or broken minting paths); if a grace period is truly needed, ALSO denylist a hash of the raw token so jti-less
  tokens are revocable; (b) make the audit outcome truthful — "no jti on token; revocation not possible (legacy token)" when
  nothing was written, and assert `rowCount=1` on the denylist INSERT before claiming revocation.

## P3 — hygiene

### P3-1 · Denylist rows live 13h regardless of the token's real TTL
- **Where:** `server/src/app.js:188` — `const exp = new Date(Date.now() + 13 * 3600 * 1000)` is hardcoded "beyond the longest TTL";
  measured row: `revoked_at 09:02:40.813 / exp 22:02:40.813` (TTL 12:59:59) for a token whose own `exp` was **90 s**.
- **Impact:** pure bloat today (the check is equality-based, so early expiry can't bypass revocation), but the row's `exp` column
  lies about the guarantee and the opportunistic cleanup keeps dead rows for hours.
- **Suggested fix:** `exp = new Date(Math.min(req.auth.exp * 1000, Date.now() + 13 * 3600 * 1000))`.

### P3-2 · Missing-state roster bridge over-matches duplicate roster names (one submission clears 3 rows)
- **Where:** `server/src/plugins/teacher.classroom/index.js:173-184` — `lower(su.name) = lower(st.name)` matches every same-named
  roster student (seed produces 6× Diya Nair, 6× Rohan Singh, …).
- **Repro (measured):** missing-state listed **3** "Diya Nair" rows on the past-due homework; after the grade-8 user submitted once,
  **0** rows — two grade-8 Diya Nairs and one grade-10 Diya Nair were all marked "not missing" by one child's submission.
- **Suggested fix:** same structural student link as P1-1; interim: require grade (and section) equality in the bridge and fail
  closed on ambiguity (row stays "missing" — the teacher asks the class, which is the safe default).

### P3-3 · Copilot accepts unbounded question length
- **Where:** `server/src/plugins/coord.view/index.js:548-550` — `String(req.body?.question ?? '').trim()`, no length cap;
  a 5 000-char question returned 200.
- **Suggested fix:** cap at ~500 chars with the plain-language 400 the codebase already uses.

### P3-4 · Duty allocate validates candidates before checking the data plane exists → misleading 400 instead of the honest 409
- **Where:** `server/src/plugins/coord.view/index.js:357-371` — with `duty.assignment` absent (P1-2), a valid request answers
  400 "Every candidate must be an active teacher" (my candidates WERE active teachers) instead of the designed
  409 "duty roster data plane is not built yet".
- **Suggested fix:** move the `tableExists(c,'duty','assignment')` check above candidate validation.
